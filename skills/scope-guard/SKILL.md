# Scope Guard

Protect margin without damaging the relationship. Every client ask gets classified, then answered with a template that keeps the door open.

## Inputs

- The client's request (verbatim if possible)
- The agreed scope (proposal/contract text, or the user's summary)
- Current project status and remaining budget/hours if known

## Classification

Classify into exactly one:

| Class | Test | Response |
|---|---|---|
| **In scope** | Named in deliverables, or a reasonable interpretation of one | Just do it; confirm briefly |
| **Grey** | Not named, but small (< 1 hour) and strengthens the relationship | Do it once, label it as a courtesy, set the precedent |
| **Change order** | New deliverable, or expands an existing one materially | Quote it separately; work continues on original scope |
| **Decline** | Outside the user's expertise, conflicts with timeline, or ethically/legally risky | Decline with a referral or alternative |

When the scope document is vague, default to **Change order** and say the scope was unclear — never absorb the ambiguity silently.

## Reply templates

**In scope** — 2 sentences: confirm, give the date it lands.

**Grey** — "Happy to include this one as a courtesy — it's outside what we scoped, so for similar additions going forward I'll send a quick quote first." One sentence, then do it.

**Change order** —
1. Acknowledge the request neutrally (no "unfortunately").
2. State it's outside the agreed scope, citing the relevant line.
3. Offer a price + timeline for the addition OR offer to swap it for an existing deliverable of similar size.
4. Confirm the original timeline is unaffected either way.
5. Ask for a decision by a date.
Under 120 words.

**Decline** — state what you can't do, why (one clause), and one concrete alternative (another provider, a simpler version, a later phase).

## Rules

- Never say "scope creep" to the client.
- Price change orders at the user's standard rate × estimated hours × 1.2 (context-switch premium). Show the user the math; show the client only the number.
- If three grey-area requests accumulate on one project, flag it to the user: time for a change order conversation.

## Output

1. Classification + one-line justification.
2. The reply, ready to send.
3. (Change order only) the internal math.
